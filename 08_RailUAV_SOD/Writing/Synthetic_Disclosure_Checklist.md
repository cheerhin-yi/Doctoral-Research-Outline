# 合成缺陷披露清单（fidelity–utility 审计）

状态：**DRAFT · IDLE**。日期：2026-09-24。  
动机：RailFOD23 已占「大量合成」叙事 → A 必须升级为**可审计披露 + 比例–性能曲线**，而非再堆生成。

## 1. 审计目标

回答：合成在什么比例、什么缺陷类型上提升封闭集效用，以及 fidelity 缺口如何披露——不是「我们生成了更多图」。

## 2. 披露字段（投稿前必填）

| 字段 | 内容 | 状态 |
|---|---|---|
| 生成器类型 | 渲染 / 拷贝粘贴 / 风格迁移 / 扩散 / 其他 | TODO |
| 版本与种子 | 软件版本、随机种子、配置哈希 | TODO |
| 源域/目标域 | 纹理与几何来源；是否含真实缺陷纹理 | TODO |
| 合成比例 | train 中合成占比；val/test 是否含合成 | TODO |
| 类别覆盖 | 哪些 part×defect 依赖合成 | TODO |
| 混测声明 | 合成是否进入 test（默认否） | TODO |
| 已知伪影 | 列表（光照、边缘、重复纹理等） | TODO |
| 许可 | 源资产许可是否允许再分发 | TODO |

## 3. Fidelity–Utility 曲线（授权后）

- 横轴：合成占比（0%, 25%, 50%, …）或合成实例数。  
- 纵轴：封闭集主指标（如 mAP50、稀缺缺陷 Recall）。  
- 对照：仅真实；真实+合成；仅合成（若伦理/许可允许）。  
- 同步报告：真实稀缺类上的增益是否消失（防「合成刷分」）。

## 4. 与 RailFOD23 划界句（草案）

RailFOD23 展示了合成异物数据的可行性；本工作不重复「再造合成集」，而提供面向小部件缺陷的 **fidelity–utility 审计协议与披露清单**，并默认隔离测试集中的合成污染。

## 5. 失败条件

若曲线无增益或 fidelity 无法诚实披露 → 缩小合成主张，仅保留真实数据 + 稀缺性说明。
