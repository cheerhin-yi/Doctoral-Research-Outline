# Taxonomy 草稿（A1 · 案头 · 未冻结终版）

状态：**DRAFT · IDLE**。定稿需 A0 通过 + 类目评审。日期：2026-09-24。

## 1. 设计原则

1. 轴1 = **小部件（part）**；轴2 = **缺陷细类（defect）**；实例 = part×defect（允许 part=正常/无缺陷）。  
2. **超越扣件-only**：RFDD 已覆盖高铁扣件全景真实缺陷 → 本基准须显式包含扣件以外的部件族，避免 Sci Data 同质。  
3. UAV 视角可分辨为先；过小/需接触式测量的缺陷降为「可选/稀缺披露」。  
4. 与 UAV-RSOD / RailFOD23 / RFDD 提供**映射表**（等价 / 粗化 / 不覆盖）。

## 2. 部件族（候选 · 待冻结）

| 族 | 候选类 | 纳入理由 | 风险 |
|---|---|---|---|
| 扣件系统 | 扣件、弹条、螺母/螺栓、垫圈 | 与 RFDD 可对照；UAV 可见 | **重叠** → 细类与视角必须差异化 |

## 4. RFDD 重叠应对（写作必写）

- RFDD：扣件全景 + 计量学缺陷（地面/近景取向）→ A **UAV 航拍尺度与视角** + **多部件族** + **标注效率/合成审计**。  
- 禁止摘要写「首个扣件缺陷集」。  
- 映射表至少：RFDD 类 → A 类（多对一允许）。

## 5. Split 原则（预声明）

场景/航次/线路隔离；禁止近邻帧跨 train/val/test；合成数据默认不进 test（若进须在披露清单标明）。

### 7.3 难度 → 发表含义（摘要）

- **低难度族为主 + 弱审计** → 工作下限；发表下限偏 **JCR Q3** 应用/方法相关（Electronics/Sensors 同档）；难撑 Sci Data 中位。  
- **多族 UAV + 真实缺陷 + 双审计** → 工作中上；发表中位 **Sci Data**；上限 Sci Data 顺利 / 冲刺 D&B。  
- 增族原则：只增 **UAV 可分辨** 且能写进映射表的族；采集困难可标「稀缺披露」或推迟，不硬凑规模。
