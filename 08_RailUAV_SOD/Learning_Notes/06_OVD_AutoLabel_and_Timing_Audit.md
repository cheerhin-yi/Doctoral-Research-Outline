## 第一部分：应知

### 学习目标

1. 能说明双引擎（文本提示 + 视觉提示）在本篇中的角色与失败模式。  
2. 能复述 D4 式受控计时：从零 vs 预标注+修正，以及加速比、接受率、修错率、Kappa、误差模式。  
3. 能列出至少三条「禁止写法」（未受控体感加速、用测试集调提示不披露、把告警指标当 A 主结果）。  
4. 能解释相对 DART：A **不卖管线发明**，卖受控人时/质量曲线。

### 知识链

```text
封闭集标注成本高
  → OVD/开词表检测器作预标注
  → E1 文本提示 + E2 视觉提示（抑制歧义）
  → 输出：框 + 引擎 ID + 提示词版本哈希
  → 人工修正
  → 与从零标注对照（顺序平衡）
  → 人时/实例、接受率、修错率、Kappa、误差模式
  → 主张：受控效率可审计（不是「又一条管线」）
```

### 术语表（CN / EN）

| 中文 | English | 一句话 |
|---|---|---|
| 开词表检测 / OVD | open-vocabulary detection | 用文本/视觉提示定位未见类或稀缺类的检测器族 |
| 预标注 | pre-label / auto-label | 机器先出框，人再改 |
| 文本提示 | text prompt | 用类别短语驱动 |
| 视觉提示 | visual prompt | 用示例图/框抑制歧义 |
| 接受率 | acceptance rate | 预标注几乎不改即采用的比例 |
| 修错率 | correction rate | 需要改动的比例/幅度统计 |
| 加速比 | speedup | 从零人时 / 预标注+修正人时（同协议） |
| Kappa | Cohen's Kappa | 一致性系数 |
| 误差模式 | error mode | 漏检/过检/错类/框漂移等 |

### 通俗讲解：OVD 是「助理」，不是「告警哨兵」

#### 1. 为什么数据文需要计时审计

Sci Data 类读者会问：你的标签从哪来？多贵？机器预标注省了多少时间、又引入了哪些系统性错误？  
「感觉快了」无法复核 → **必须受控计时**（D4 草稿）。

#### 2. 双引擎在干什么（机制）

- **E1 文本提示：** 用「弹性扣件/弹条」等短语出候选框。失败：同义词、线路术语差异、背景金属干扰。  
- **E2 视觉提示：** 用少量示例抑制文本歧义。失败：示例域偏移（近景示例去标航拍）、姿态覆盖不足。  
- **输出纪律：** 框 + 引擎 ID + 提示词版本哈希——否则无法复现审计。

#### 3. D4 流程（学习版）

```text
冻结子集与类目
  → 标注员培训与合格测验
  → 条件 A：从零标注；条件 B：预标注+修正（顺序平衡，避免总是先做容易的）
  → 录时（到实例或到框的协议写死）
  → 抽检与双人一致性 → Kappa
  → 误差模式计数表
  → 写入 Technical Validation（不是 Related Work 吹牛）
```

#### 4. A 主指标表

| 指标 | 用途 |
|---|---|
| 时间/实例 | 加速比核心 |
| 接受率 | 预标注可用性 |
| 修错率 | 仍要花的成本 |
| Cohen's Kappa | 人与人 / 人与修正后一致性 |
| 误差模式计数 | 漏检/过检/错类/框漂移 |

#### 5. 不是 A 主指标（划给 B）

固定告警预算下的危险召回、风险排序 AUPRC、可派发队列 → **B**。  
提示词资产可以与 B「同资产」共享，但本篇只报**标注侧**影响（见 `09`）。

#### 6. 相对 DART

DART 已展示 DreamBooth+Grounding DINO 类半自动管线。A 若再卖「我们发明了管线」易同质；应卖**受控人时与误差模式可审计**。

### 常见错误 / 禁止说法

| 禁止 | 改法 |
|---|---|
| 「显著提升开放世界告警召回」 | 改写为人时/Kappa/误差模式 |
| 「感觉快了约 3 倍」无协议 | 受控计时 + 子集冻结 + 顺序平衡 |
| 在 test 上调提示词不披露 | 披露调参集合；或禁止用 test 调 |
| 把 OVD 写成在线告警模块 | 角色降为预标注工具 |

### 补充课：计时表最小列集（可贴进 Validation）

| 列 | 含义 |
|---|---|
| condition | from_scratch / prelabel+fix |
| annotator_id | 匿名化即可 |
| order | AB 或 BA（顺序平衡） |
| seconds_per_instance | 主加速比输入 |
| accept_rate | 几乎不改即采用 |
| edit_rate_class / edit_rate_box | 分列修错 |
| kappa | 一致性 |
| error_mode_counts | 漏检/过检/错类/框漂移 |

没有 `prompt_hash` 与 `engine_id`，这张表无法复现——预标注输出必须带走元数据。

### 补充课：三句角色纪律（背下来）

1. OVD 在 A = 预标注助理。  
2. D4 主结果 = 人时与质量，不是告警召回。  
3. 删掉所有 B 句后，D4 主表仍应完整。


### 补充课：从「感觉快了」到可辩护加速比

加速比只在同时满足时成立：子集冻结、条件对照、顺序平衡、录时粒度写死、失败预标注仍计入预标注条件。缺任一条件，只可写探索性观察，不可写主结果加速比。

视觉提示补的是文本歧义，不是万能药：近景示例去标航拍会造成域偏移——必须披露示例来源。


### 补充课：双引擎失败模式对照表

| 引擎 | 典型失败 | 人修时常见动作 |
|---|---|---|
| E1 文本 | 同义词/线路术语差异；背景金属误触发 | 改类、删框、收窄提示词 |
| E2 视觉 | 近景示例→航拍域偏移；姿态覆盖不足 | 换示例、补对称股、改框 |

审计要回答的不是「哪个引擎更酷」，而是：在冻结提示词版本下，人时与误差模式如何变化。

### 补充课：与 DART 的一句话划界（可背）

「DART 展示了半自动管线可行性；本工作不宣称发明新管线，而报告受控人时、接受率、修错率、Kappa 与误差模式。」

### 补充：从零 vs 预标注+修正——计时公平性

受控计时若一边「从零」一边「预标注」，必须对齐：

1. **同一子集、同一类目版本、同一显示 UI。**  
2. **顺序平衡：** 一半标注员先 A 后 B，一半相反，避免学习效应全算在某一边。  
3. **录时粒度写死：** 按实例 / 按图像 / 是否含休息，三者选一并披露。  
4. **预标注失败也要计时：** 「打开预标注 → 发现全错 → 清空重标」仍算预标注条件成本，不能偷偷改记到从零。

### 补充：Kappa 在本篇的位置

- Kappa 回答「人与人是否一致」，不是「模型 mAP」。  
- 预标注可能抬速度但伤一致性：两者都要报。  
- 若 Kappa 低：先修协议与培训，再谈加速比宣传。

### 补充：与 B 的「同资产不同主结果」口诀

```text
同一套提示词 / 术语表
  → 在 A：只影响标注人时与误差模式表
  → 在 B：才允许进入告警预算/风险排序实验（且 B 独立成文）
A 文删光 B 句后，D4 主表仍应能独立站住
```


### 补充：预标注输出必须带走的元数据

每一框建议绑定：`engine_id`（E1/E2）、`prompt_hash`、`model_ckpt`、`image_id`、`timestamp`。  
没有这些，D4 表格无法回答「加速来自哪一版提示词」。

### 补充：接受率 vs 修错率不要混用

- 接受率高、修错率低：预标注可用。  
- 接受率高但最终 Kappa 低：可能「懒得改」而非「真对」——抽检必须独立。  
- 修错率按「改类 / 改框 / 增删框」分列，比单一百分比更有诊断力。
