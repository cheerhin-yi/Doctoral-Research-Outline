### 2. 双引擎机制与失败模式

- **E1 文本提示：** 用「弹性扣件/弹条」等短语出候选框。失败：同义词、线路术语差异、背景金属干扰。
- **E2 视觉提示：** 用少量示例抑制文本歧义。失败：示例域偏移（近景示例去标航拍）、姿态覆盖不足。
- **输出纪律：** 框 + 引擎 ID + 提示词版本哈希——否则无法复现审计。

### 3. D4 流程与 A 主指标表

```text
冻结子集与类目
  → 标注员培训与合格测验
  → 条件 A：从零标注；条件 B：预标注+修正（顺序平衡）
  → 录时（到实例或到框的协议写死）
  → 抽检与双人一致性 → Kappa
  → 误差模式计数表
  → 写入 Technical Validation
```

| 指标 | 用途 |
|---|---|
| 时间/实例 | 加速比核心 |
| 接受率 | 预标注可用性 |
| 修错率 | 仍要花的成本 |
| Cohen's Kappa | 一致性 |
| 误差模式计数 | 漏检/过检/错类/框漂移 |

**不是 A 主指标（划给 B）：** 固定告警预算下危险召回、风险排序 AUPRC、可派发队列。提示词资产可与 B「同资产」共享，但本篇只报**标注侧**影响。

相对 DART：不卖管线发明；卖**受控人时与误差模式可审计**。

| 禁止 | 改法 |
|---|---|
| 「显著提升开放世界告警召回」 | 改写为人时/Kappa/误差模式 |
| 「感觉快了约 3 倍」无协议 | 受控计时 + 子集冻结 + 顺序平衡 |
| 在 test 上调提示词不披露 | 披露调参集合；或禁止用 test 调 |
| 把 OVD 写成在线告警模块 | 角色降为预标注工具 |
