## 第一部分：应知

### 学习目标

1. 能闭卷复述 D0–D5 每一类的含义，并各举一个 UAV 可见/不可见边界例。  
2. 能区分「部件类（part）」与「缺陷类（defect）」两轴；理解实例 = part×defect（允许正常）。  
3. 能用巡检/数据文可接受的中文描述缺陷，而不冒充未核验的标准条文或伤损等级。  
4. 能说明 D5、忽略区与主 mAP 的接口，避免用质量问题粉饰检测分数。

### 知识链

```text
先认部件（part）
  → 再判外观状态（defect）
  → D0 正常对照
  → D1 缺失 / D2 可见断裂裂纹 / D3 松脱位移 / D4 宏观腐蚀剥落
  → D5 遮挡或不可判定（质量类）
  → 多标签？忽略区？稀缺披露？
  → 哪些进主 mAP，哪些单独报
```

### 通俗讲解：两轴，不要揉成一锅粥

#### 1. 为什么要 part × defect

- **机制：** 同一个物理位置上的「弹条」可以是完好的（D0），也可以整件不见（D1），也可以歪了（D3）。若只用一个标签「坏弹条」，统计时无法回答：缺了多少、歪了多少、正常对照有多少。  
- **数据文需要：** 可复现的外观操作定义 + 可分的评价轴。  
- **类比（辅助）：** 像存货盘点：先认「是什么零件」，再认「状态是缺货/变形/锈蚀」，而不是发明一个无法对账的「坏东西」类。

#### 2. 逐码讲清「可见边界」

**D0 正常：** 在约定视角与最小像素下，部件外形完整、位置在期望交点附近。没有 D0，模型很难学会「这里应该有东西」。

**D1 缺失：** 对称位置或协议定义的「应出现位置」上，该部件不见。注意：被道砟完全盖住是「看不见」→ 倾向 D5，不是武断 D1。

**D2 可见断裂/裂纹：** 外观上有宏观开口或断裂缝。显微裂纹、需渗透探伤才知的缝 → **不要硬塞主类**。

**D3 松脱/位移：** 部件还在，但姿态/位置相对期望明显偏移。协议要写：相对什么参考（轨向、枕边、螺母对中等）。

**D4 宏观腐蚀/剥落：** 大块锈蚀或表层脱落，和「一层灰/水渍」要有书面区分规则（例如：是否改变金属轮廓、是否大面积颜色+纹理共现等——具体阈值冻结时再定，学习阶段先有「必须有协议」意识）。

**D5 遮挡/不可判定：** 看了但判不了。这是**质量/可见性**问题，不是又一种「缺陷花样」。

#### 3. 巡检语言（诚实版）

**可写：** 外观可见缺失、可见裂纹、明显错位、大面积锈蚀剥落、被遮挡无法判定。  

**无引证时勿写：** 具体伤损等级代号冒充国标、未测量的「紧固力矩不合格」、内部伤损断言、「已达某级伤损需立即下道」等作业结论。

数据文读者要的是**可复现的外观操作定义**，不是假装你做了探伤或调度决策。告警/派发属于 **B**（见 AB Boundary）。

#### 4. D5 vs 忽略区

| | D5 | 忽略区 |
|---|---|---|
| 含义 | 标注员看了，但状态不可判定 | 协议规定本帧/本区**不参与评价** |
| 例子 | 半掩埋弹条、强阴影下轮廓不清 | 列车占满画面、明确划定的忽略多边形 |
| 评价 | 通常不进主 mAP 或单独质量统计 | 不计入该区域的 TP/FP 统计（按协议） |

二者在 Data Records 必须写清，否则审稿人会认为你在用「难例消失术」抬 mAP。

#### 5. 与评价接口（预声明）

- 主表建议：对 D1–D4（或冻结后的主缺陷集）报检测指标；D0 作对照；D5 单独质量统计。  
- 稀缺真实缺陷：宁可披露样本量小，也不用合成冒充真实（合成走 `07`）。  
- 多标签是否允许：未冻结前标 **Unknown/待决**；练习时按「单主缺陷码」思考即可。

### 常见错误 / 禁止说法

| 禁止 | 原因 | 改法 |
|---|---|---|
| 「国标 D3=松脱」无出处 | 冒充标准 | 「项目工作码 D3；未引证国标」 |
| 把 D5 算进主 mAP 当缺陷类刷分 | 扭曲数据质量评价 | D5 单独报或忽略规则 |
| 显微裂纹硬进 D2 主类 | 标签不可复现 | 稀缺披露或排除 |
| 脏污一律打 D4 | 无区分协议 | 先写外观区分规则 |
| 用告警等级语言当标签 | 滑向 B | 只写外观状态 |

### 必答题

1. 为什么 D0（正常）对缺陷检测数据集几乎是必需的？  
2. D2 的「可见」边界如何防止把显微裂纹硬塞进主类？  
3. 把 D5 算进主 mAP 会怎样扭曲对数据质量的评价？

---

### 参考答案

#### 练习 1 参考

- D0：在轨–枕交点附近可见完整弹条轮廓，姿态与邻侧正常件大致一致。  
- D1：交点附近期望位置无弹条外形，且排除被协议定义的完全遮挡情形。  
- D3：弹条仍可见，但相对轨向/枕边的扣压位置明显偏移或张开超出协议阈值。

#### 练习 2 参考

例规：仅表面颜色变深但金属外轮廓完整、无片状脱落边缘 → 不标 D4；出现片状脱落、轮廓缺损或大块层状锈皮 → 才考虑 D4。水渍/油污单独作为干扰因素进质量说明，不自动等于腐蚀。

#### 练习 3 参考

应收缩「可用性」主张：承认大量区域不可判定，主评价应报告有效可标面积/实例比例；必要时缩小场景范围或降低航高（未来采集），而不是声称「全线路可检」。

#### 必答 1 参考

没有正常对照，模型与标注协议都难以定义「应该存在」；缺失类（D1）在统计与训练上会与背景混淆，数据集也难以证明「不是只拍坏的」。

#### 必答 2 参考

把 D2 限定为 UAV 约定 GSD/像素下**宏观可辨**的开口或断裂；达不到可辨阈值的标稀缺/排除，并禁止用探伤结论回填标签。

#### 必答 3 参考

D5 混入主缺陷类会把「看不清」当成「检出目标」，mAP 可能虚高或乱抖，掩盖采集/标注质量问题，让 Technical Validation 失去「证明数据用得起来」的意义。
