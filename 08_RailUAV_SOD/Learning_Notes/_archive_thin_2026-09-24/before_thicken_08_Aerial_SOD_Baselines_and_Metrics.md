## 第一部分：应知

### 学习目标

1. 能说明数据文 Technical Validation 里「同协议基线表」最少应固定哪些轴（数据划分、输入尺度、置信度/NMS、类别集、硬件披露）。  
2. 能把小目标/稀缺缺陷指标与 D0–D5、忽略区规则对齐。  
3. 能区分「基线证明数据可用」与「方法文刷 SOTA」。

### 知识链

```text
冻结 taxonomy 与 split
  → 选择封闭集检测器族（YOLO / RT-DETR…）
  → 同协议训练/评价设定
  → 主指标：mAP 等 + 稀缺缺陷 Recall 等（待冻结）
  → 小目标/原图像素协议（与视角笔记衔接）
  → 失败边界例（漏检模式）
  → 回链 Run ID（授权后）
  → 写入 Technical Validation（非 Related Work 吹牛）
```

### 链上说明

1. **同协议**  
   - 换模型可以；换数据划分、换忽略区定义、换测试是否含合成 → 表不可比。  
   - 未授权前：只学「表轴」，不跑主 Run。

2. **建议表轴（清单意识）**  
   - 模型与权重来源；输入尺寸；增强是否用于 val/test；置信度与 NMS；类别映射；split 哈希；硬件；随机种子。  

3. **与 Practice 小目标口径的关系**  
   - 原图尺度上的 small 定义、召回口径可借鉴 Practice `04`；但铁路部件阈值要按本项目冻结，**不要**照抄 VisDrone 面积阈值当铁路标准。

4. **失败例**  
   - 数据文需要「边界失败」证明你理解域：强阴影弹条、砟掩埋、远端尺度断崖等。

### 练习

1. 草拟一张空基线表表头（列名即可）。  
2. 写一句合规 Validation 句、一句违规「我们提出了更强检测器」句。  
3. 说明：若仅真实稀缺类 Recall 很低，合成曲线却很高——主张应如何并列披露。

### 必答题

1. 为什么基线模型本身通常不算 A 的 novelty？  
2. 忽略区定义改变却不披露时，mAP 比较会发生什么？  
3. Technical Validation 里最少要让读者复现哪三件事？
