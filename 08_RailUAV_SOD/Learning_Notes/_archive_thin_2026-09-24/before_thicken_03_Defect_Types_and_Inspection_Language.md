## 第一部分：应知

### 学习目标

1. 能闭卷复述 D0–D5 每一类的含义，并各举一个 UAV 可见/不可见边界例。  
2. 能区分「部件类（part）」与「缺陷类（defect）」两轴；理解实例 = part×defect（允许正常）。  
3. 能用巡检/数据文可接受的中文描述缺陷，而不冒充未核验的标准条文或伤损等级。

### 知识链

```text
先认部件（part）
  → 再判外观状态（defect）
  → D0 正常对照
  → D1 缺失 / D2 可见断裂裂纹 / D3 松脱位移 / D4 宏观腐蚀剥落
  → D5 遮挡或不可判定（质量类）
  → 多标签？忽略区？稀缺披露？
  → 哪些进主 mAP，哪些单独报
```

### 工作码表（候选 · 待冻结）

| 码 | 细类 | 说明 | UAV 标注提示 |
|---|---|---|---|
| D0 | 正常/完整 | 对照类 | 必需；支撑「缺失」可学 |
| D1 | 缺失 | 应在位置不见该部件 | 优先；左右股对照有用 |
| D2 | 断裂/裂纹（可见） | 宏观可辨 | 显微裂纹 → 稀缺或排除 |
| D3 | 松脱/位移 | 位置/姿态异常 | 需尺度/姿态约定 |
| D4 | 腐蚀/剥落（宏观） | 大块锈蚀或表层脱落 | 与脏污/水渍要有区分协议 |
| D5 | 遮挡/不可判定 | 质量类 | **不进主 mAP** 或单独报 |

### 链上说明

1. **两轴设计**  
   - 轴1 部件族（扣件、鱼尾板…）；轴2 缺陷细类。  
   - 同一弹条可以是 D0 或 D1；不要把「弹条」和「缺失」揉成无法统计的单标签（除非协议明确允许多标签）。

2. **巡检语言（诚实版）**  
   - 可写：外观可见缺失、可见裂纹、明显错位、大面积锈蚀剥落、被遮挡无法判定。  
   - 慎写/勿写（无引证时）：具体伤损等级代号、未测量的「紧固力矩不合格」、内部伤损断言。  
   - 数据文读者要的是**可复现的外观操作定义**，不是假装你做了探伤。

3. **D5 与忽略区**  
   - 列车占满画面、强阴影、运动模糊 → 可标忽略或不计入主指标。  
   - D5 是「看了但判不了」；忽略区是「协议规定本帧/本区不评」。二者在 Data Records 里要写清。

4. **与评价的接口**  
   - 主表建议：对 D1–D4（或冻结后的主缺陷集）报检测指标；D0 作对照；D5 单独质量统计。  
   - 稀缺真实缺陷：宁可披露样本量小，也不用合成冒充真实（合成走 `07` 审计）。

### 练习

1. 为「弹条」各写 D0/D1/D3 的一句话外观定义（给标注员看的那种）。  
2. 举一例：脏污被误标成 D4——你的区分规则是什么？  
3. 说明：若某图 `D5` 占比极高，对「数据集可用性」主张应如何改口。

### 必答题

1. 为什么 D0（正常）对缺陷检测数据集几乎是必需的？  
2. D2 的「可见」边界如何防止把显微裂纹硬塞进主类？  
3. 把 D5 算进主 mAP 会怎样扭曲对数据质量的评价？
