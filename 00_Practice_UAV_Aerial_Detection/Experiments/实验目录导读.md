# 实验目录导读（Experiments）

> 写给人看的说明。`papers/P0_EI/Run_Index.md` 是给 AI 用的登记表，**你不需要读**。

## 1. 一句话用途
这里放练手论文 P0_EI 的全部实验：同一个冻结的 YOLO11n 权重，在 VisDrone 和 UAVDT 上比较 5 种推理方式（F640 / F1280 / DensK1 / UnifAll / SAHI640）的精度和速度。

## 3. 每个 Run 回答了什么
（路径相对 `papers/P0_EI/`；具体数字以报告为准）

| Run | 回答的问题 | 结论 | 报告 |
|---|---|---|---|
| A | 环境、权重、类别映射是否冻结好？ | PASS，已冻结 | `00_freeze/Environment_Freeze.md` |
| B | 5 种方式在 GTX 1660 SUPER 上各多快？ | PASS；数值见报告 | `04_timing/StageB_Timing_Report.md` |
| C | 在 48 张开发图上流程是否跑通、怎么选通道？（非主表） | PASS；数值见报告 | `01_visdrone_main/StageC_Cal48_Dev_Report.md` |
| D | VisDrone test-dev 上 5 种方式精度如何？ | PASS（只说明流程完成）；数值见报告 | `01_visdrone_main/StageD_TestDev_Report.md` |
| E | 换到 UAVDT（50 序列 / 40735 帧）结论还成立吗？ | DONE / PASS；数值见报告 | `03_cross_uavdt/StageE_UAVDT_Report.md` |
| F | 逐图配对后，F1280 是否真的比 DensK1 好？ | 是：small recall +0.0409，CI [0.0355, 0.0462] | `02_paired_stats/StageF_Paired_Stats_Report.md` |
| G | 换 RTX 5060 Ti 后精度一致吗、谁更快？ | PASS；精度一致（|Δsmall recall| ≤ 0.014 个百分点）；F1280 比 DensK1 快（逐图中位差 −13.32 ms） | `04_timing/Timing_5060Ti_Table.md` |
| H | UAVDT 上做配对统计 + 序列级 bootstrap，是否仍显著？ | PASS；主对序列 CI [0.010, 0.040]；Stage F 可逐位复现 | `03_cross_uavdt/H_UAVDT_Paired_Stats_Report.md` |
| I | 按输入像素归一化后，时延由什么决定？ | 主要由前向次数决定；同像素 UnifAll vs SAHI640 recall 0.451 vs 0.218 | `04_timing/Pixel_Latency_Table.md` |
| J | 复现附录缺的设置补齐了吗？有失败例吗？ | PASS；SAHI 实际合并为 GREEDYNMM；6 例裁图 | `05_packaging/Reproducibility_Appendix.md` |
| K | 不同密度下 F1280 都优于 DensK1 吗？ | VisDrone 各箱均为正且 CI 不含 0；UAVDT 最稀疏箱打平 | `06_density_slices/K_Density_Slices_Report.md` |

注：1660 上 F1280 与 DensK1 时延差异不显著（p=0.235），说时延必须分 GPU 写。

## 6. 不要改、不要删
- 脚本里写的是**固定路径**：移动或改名任何文件夹都会让脚本和复现失效。
- `00_freeze/script_sha256.txt` 记录脚本指纹：改脚本一个字就对不上。
- `00_freeze/` 里的冻结 JSON 即使有旧名字也不改（例如 stage_e 配置里的 smoke run_id）。
- `preds/` 和 `data/` 是证据，删了无法补回（需重新推理）。
