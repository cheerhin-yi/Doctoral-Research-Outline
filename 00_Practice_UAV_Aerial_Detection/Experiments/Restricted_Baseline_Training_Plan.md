## 1. 此次训练要解决什么

当前没有已准入的VisDrone十类YOLO11n权重，无法观察真实P3/P4弱响应，也不能据此支持或否定候选。采用一组普通检测器训练，全图、局部和所有选区对照共享同一个末轮checkpoint。既有[权重审查](Weight_Source_Audit.md)、[训练接口](Training_Interface_Audit.md)、[50项标签检查](Label_Adapter_Check.md)和[评价兼容核验](Official_Runtime_Crosscheck.md)直接复用。

| 判断层次 | 本次交付／后续证据 | 不成立时怎样处理 |
|---|---|---|
| 普通权重可用 | 十类、数据／初始化／软件身份可追溯，100轮完成，损失与输出有限，末轮权重可重新加载 | 环境或训练失败，保留记录；不是候选被否决 |
| 弱响应有额外选择价值 | 后续固定片数比较低阈值、P3-only、原始跨层乘积、移位P4和完整候选 | 简单替代解释收益则停止候选 |
| 同整帧预算值得采用 | 后续计入响应读取、归一化、全部检测与合并费用 | 开销抵消收益则停止，不叠加模块 |

本次只执行第一层所需的一组训练及输出完整性预检。后两层仍按候选报告执行，不先训练候选专用模型。单seed只用于探索；不能据此宣称稳健增益、正式论文结论或国奖资格。没有LLM、VLM或其他新增模型模块。

## 2. 数据范围与接触边界

验证集合采用现有作者一致的val ZIP（548图，SHA256 `abeea063037e5d20398837deb11084e652402a34ddf4f207bdf541a6f2a35ef9`）。沿用原协议：按UTF-8编码的`SHA256("diag-v1:" + 不含目录的图像文件名)`十六进制升序，冲突按文件名Unicode顺序，前48图为cal48，其余500图为diag500。只根据既有图像清单生成排序，不按标签或预测重抽；清单落地后保存SHA。

**cal48用途的小范围调整必须随本方案一并批准**：从仅计时／流程检查扩为普通训练的固定监控集合及训练后完整性检查。每轮原生验证只读这48图；不根据其AP选择轮数、参数或权重。diag500不进入训练配置、验证加载器、checkpoint选择或本次训练后检查，后续仅作探索性候选对照。test-dev不进入此执行链，既有来源组Unknown及共享场景限制保留；cal48、diag500均不得称来源独立测试。

真实转换只能在新建的`11_Datasets/processed/VisDrone/BT1/attempt_01/`执行：安全解包train和cal48所需图像／标签，拒绝路径穿越、缺失及覆盖；调用现有单文件转换逻辑，增加批量清单包装而不重写语义。逐图保存尺寸、原标注哈希、行级处理原因和派生哈希；核对6471个train、48个cal48图像—标签配对及总行数守恒。无效几何按已有规则逐行排除，包括已定位的3条零高记录，不删整图。遇新增不符合规则的行立即停止，不自动修复或放宽转换器。

## 4. 固定训练与选模规则

| 项目 | BT-1选择及理由 |
|---|---|
| 训练 | 100个完整epoch，seed=0，imgsz=640，batch=4，device=0，workers=0；一组训练，不搜超参数 |
| 数值与资源 | FP32、amp=false、cache=false、compile=false、deterministic=true；适配已知6GiB显卡的保守起点，不保证能运行 |
| 优化 | SGD，lr0=0.01、lrf=0.01、momentum=0.937、weight_decay=0.0005、warmup=3、nbs=64，保持固定版本的标准累积／调度实现；不使用auto优化器 |
| 数据处理 | 固定版本普通detect默认增强，不另提出增强创新；mosaic=1、末10轮关闭、fliplr=.5及默认HSV／平移／缩放显式记入spec；不加mixup、蒸馏、类别权重或自定义损失 |
| 监控 | cal48每轮原生验证只看训练健康，不做官方指标结论；patience=0禁用精度早停；已静态核对该版本将0转为无穷等待 |
| 保存 | 每轮last与框架best均保留，另每10轮存档；**只准入第100轮last的EMA模型**，不用best择优；复制前保留含epoch／优化器的末轮原件及哈希，最终清理版另存并关联 |
| 完整性检查 | 训练后仅cal48固定排序前10图、全图640、batch1、FP32；确认十类输出、坐标、有限值和P3/P4响应导出形状。无切片策略、无性能比较 |

上述100轮是预先选择的受限诊断配置，不是收敛保证。损失、监控曲线及每类输出如实保留；未充分训练、输出坍塌或没有可恢复小目标证据时，结论为“基线／诊断证据不足”，不能直接否决弱响应机制。需要延长轮数或第二seed时单独提出证据理由，不能静默加跑。

固定源码[trainer.py](https://github.com/ultralytics/ultralytics/blob/07958a70205d1388612bd00f8a2f32cf769d8fed/ultralytics/engine/trainer.py)揭示的执行注意点：`val=false`仍可能末轮验证，故必须隔离数据清单；`time`会改变epoch规划，不能作为本方案限时参数；首轮OOM可能自动缩batch，NaN可能回退恢复。执行包装须禁用这些隐式恢复并捕获失败，不修改网络／损失。不得仅凭固定batch参数就声称无自动变化。

实现前先静态核对守卫位置：OOM必须在首个自动重建加载器之前终止；NaN/Inf在损失／梯度检查或验证处立即终止；不得简单永久设置`_oom_retries`计数，因为训练循环还用它判定是否重启epoch。优先使用独立、最小的执行控制包装；所有改动保存差异，仅约束失败恢复，不改变正常优化步骤。无法做到则停止准入，不带着失效守卫训练。
