## 第一部分：必须掌握

### 学习目标

1. 区分 Params / GFLOPs / 纯推理延迟 / **端到端整帧耗时** / 超时率；知道 C1/C2 各自绑定哪些量。
2. 能写出可复现的 batch=1 测速边界（含不含预处理、NMS、切片拼合）。
3. 能解释：1660SUPER 流程验证表 vs 4090 正式时序表必须分列。

### 知识链

```text
方法协议（五选一）
→ 计时边界（从读图到输出框）
→ 同步与预热
→ 单次 vs median-of-3
→ mean / p95 / 超时率
→ 与精度指标同表披露
→ 可写进论文的速度句
```

### 链上要点

1. **GFLOPs ≠ 墙钟。** 切片方法可能 GFLOPs 低但总延迟高（重复推理 + 拼合）。
2. **Stage B：** cal48 上可做 median-of-3，用于协议稳定性；**Stage D：** test-dev 为一次性 `total_ms`，服务终评与 Stage F 配对，不把 D 的均值伪装成正式 4090 表。
3. **超时率是 C2 核心副指标。** 只报平均延迟会隐藏尾部风险。
4. **同机口径。** 未跑 4090 前，正文只能写「1660SUPER 开发机时序」或明确「正式时序待补」。
5. **禁止：** 用台式 GPU 速度写「机载实时」。

### 练习

1. 为 SAHI640 画计时边界：哪些步骤必须计入端到端？
2. 比较：F1280 mean ms ≈ 33.7，DensK1 ≈ 34.1（Stage F 汇总，1660SUPER）。写一句支持「速度接近」的谨慎表述，再写一句禁止的营销表述。
3. 列出正式 4090 时序表最少列：方法、N、mean、p95、超时定义、精度列是否同 Run。

### 必答题

1. 为什么 C1 不能只用 GFLOPs 证明「更快」？
2. Stage B median-of-3 与 Stage D one-shot 混进同一「速度优势」句，错在哪里？
3. UnifAll / SAHI640 召回高或覆盖全时，为何仍可能败给时间预算叙事？
