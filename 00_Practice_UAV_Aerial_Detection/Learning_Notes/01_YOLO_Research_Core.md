2. **预测成为损失或最终检测框的机制**
   - 复述要求：讲清标签分配、损失、框解码、置信度筛选、NMS 各自解决什么问题及先后关系。
   - 验证方式：完成一组 IoU、Precision／Recall、简化 NMS 手算；并用自己的话解释 AP 与 mAP 评价什么。
3. **从错误证据回到结构环节**
   - 复述要求：区分漏检、误检、定位偏差、重复框，并说明可能关联的环节。
   - 验证方式：至少两个案例写出「现象→证据→候选原因→是否改结构」判断链。

## 🔗 主题知识链

按下面的**连接关系**组织学习（必须能顺着讲，不能只背词）：

```text
输入与预处理
  → Backbone（分层特征）
  → 多尺度特征（P3/P4/P5…）
  → Neck（融合）
  → Detection Head
  → 训练分支（匹配／损失） 与 推理分支（解码／阈值／NMS）
  → 评价指标（IoU → TP/FP/FN → P/R/AP）
  → 错误证据回流 → 是否需要改结构／改协议
```

每个环节始终追问四件事：

1. 这一环**接收**什么？  
2. 它**做了**什么？  
3. 它**输出**什么给下一环？  
4. 如果这里出错，最终会出现什么**可观察现象**？

## 为什么服务本练手论文

会调用 `predict`／`val` **不等于**理解检测链。练手文（时间预算约束小目标）要比较整图 640、整图 1280、密度单片、均匀切片时，你必须能说清：

- 分辨率与 stride 如何改变小框在特征图上的覆盖；
- 训练分支与推理分支各看什么数；
- 指标与超时率分别约束什么；
- 负结果应回流到「结构／协议／数据」哪一环，而不是盲目加模块。

## 📚 沿知识链展开（核心说明）

### 1. 输入与预处理

- **原始输入：** 常见实验设定把边长放到约 \(640\times640\) 或 \(1280\times1280\)（letterbox 等会保留长宽比并填充）。
- **张量布局：** 批量输入常写为 \(B\times C\times H\times W\)。例如 batch=64、RGB、\(640\times640\) → `[64, 3, 640, 640]`（通道维位置以框架为准，概念上是批量×通道×高×宽）。
- **训练期增强：** 翻转、颜色抖动、马赛克等通常**只在训练**；推理一般只做确定性缩放／归一化。增强若跨 split 泄漏，验证指标会虚高（详见笔记 02／03）。
- **与小目标：** 同一物体在 640 与 1280 上的像素面积差约 4 倍量级（边长×2 ⇒ 面积×4）；这是 F1280 强基线有力的原因之一，**不是**自动等于「新方法」。

### 2. Backbone：从图像到分层特征

#### 2.1 卷积块 CBS（Conv–BN–SiLU）

YOLO 族里大量基础块是：

`Conv2d → BatchNorm2d → Activation（常用 SiLU）`

| 组件 | 做什么 | 为何常见 |
|---|---|---|
| Conv | 局部感受野提特征；可用 stride 改变分辨率／通道 | 权值共享，空间结构保留 |
| BN | 规范化激活分布，稳定训练 | 利于较大学习率与融合路径 |
| Act | 引入非线性 | 无激活则多层线性可坍缩 |

顺序上 **Conv→Norm→Act（后归一化）** 在检测骨干里很常见：先提特征再规范再非线性。其他顺序（Pre-Norm 等）多见于特定残差／Transformer 写法，不是本块背诵重点。

#### 2.2 瓶颈与 C2f（直觉）

- **Bottleneck：** 常用「压缩→3×3→扩张」或两层 3×3，并可带 **shortcut（残差）**，缓解深层难训（与 `10_ResNet_Core` 直觉相通）。
- **C2f（YOLOv8 一类）：**  
  1×1 扩／理通道 → 特征拆成两路：一路短接保留细节，一路经过若干 Bottleneck → **通道维 concat** → 再 1×1 整理。  
  **目的直觉：** 用较短路径保留较浅细节、较长路径叠语义，并控制计算量（CSP／ELAN 一类思想）。  
  **你要会讲的是数据流与「为何拆分再拼接」，不是背所有通道超参。**

#### 2.3 尺度金字塔（以 640 输入为例）

反复 `stride=2` 的卷积会让特征图边长减半。概念上（具体通道以版本 yaml 为准）：

| 阶段直觉 | 相对输入 stride | 640 输入时特征边长约 | 更偏向 |
|---|---:|---:|---|
| 较浅 | 8 | 80 | 较小目标 |
| 中 | 16 | 40 | 中等目标 |
| 较深 | 32 | 20 | 大目标／强语义 |

末端常有 **SPPF**：同层多尺度池化后拼接，再卷积压回通道——用不大的代价增大感受野。

**手算练习（必做）：** 给定输入边长 \(S\) 与某层 stride \(s\)，特征边长约为 \(S/s\)（忽略 padding 细节）。写清：小框在深特征上可能只占几个格子，为何「只加深 Backbone」未必救小目标。

### 3. 多尺度特征与 Neck

- Backbone 把**不同分辨率**的特征交给 Neck。  
- Neck（FPN／PAN 一类）做 **自顶向下语义传递** 与 **自底向上定位细节回流**：上采样、下采样、相加或拼接。  
- **P3／P4／P5**（若有 P2）大致服务小／中／大目标；**加 P2** 提高小目标分辨率，但算力与内存上升；**只提输入分辨率**不改头，与「加 P2」不是同一机制。  
- 练手文语境：比较 F640 vs F1280 vs 切片时，要能说清「变的是输入／选区协议，还是 Neck／Head 结构」。

### 4. Detection Head

- 在每个尺度特征上预测：**类别**、**框**（及实现相关的目标性／分布等）。  
- 多尺度头可共享或分塔；本块只要求理解「每层各管一档尺度」。  
- Head 原始输出在**训练**进入匹配与损失，在**推理**进入解码与 NMS。  
- 历史候选「轻量共享头」见笔记 05——**不是本块必做实现**。

### 5. 训练分支

```text
图像 → Backbone → Neck → Head 原始输出
                         ↘ 与 GT 匹配（标签分配）
                         ↘ 分类损失 + 定位损失（等）
                         ↘ backward 更新权重
```

- **标签分配：** 决定哪些锚点／格子／查询负责哪个 GT；分配不稳会出现漏检或争抢。  
- **损失：** 分类项与回归项惩罚不同错误；类别不平衡、尺度不平衡会偏到某一类错误。  
- **要点：** 训练步内通常**不做 NMS**；NMS 是推理后处理。  
- 具体 YOLO 版本的匹配与损失名以你核对的文档／源码为准；本块先掌握**角色与顺序**。

### 6. 推理分支

```text
Head 原始输出 → 解码为候选框
              → 置信度阈值过滤
              → NMS（按 IoU 抑制重复）
              → 最终框列表（坐标、类别、分数）
```

- **置信度阈值↑**：通常 Precision 倾向上升、Recall 倾向下降，候选变少。  
- **NMS IoU 阈值：** 过严可能压掉密集真目标；过松留下重复框。  
- **公平实验：** 比较方法时，后处理阈值与计时边界必须声明并尽量固定（见练手文口径／EI 主张）。

### 7. 评价指标（要会手算小例子）

| 概念 | 含义（用自己的话能讲） |
|---|---|
| **IoU** | 预测框与 GT 交集面积／并集面积；衡量定位重叠 |
| **TP／FP／FN** | 在给定 IoU 阈值下：命中的预测／多报／漏报 |
| **Precision** | TP/(TP+FP)：报出来的里有多少对 |
| **Recall** | TP/(TP+FN)：真目标里找回多少 |
| **AP／mAP** | 不同召回水平上的精度综合；mAP50 与 mAP50–95 严苛程度不同 |
| **AP_small／Recall_small** | 小目标子集上的表现；练手文更关心 |

**本项目小目标常用口径：** 原图像素面积 \(0<w\times h<1024\)（以仓库声明为准）。  
**原生 Ultralytics AP ≠ VisDrone 官方兼容 AP**——写表必须标明口径。

### 8. 从错误回到结构

| 现象 | 可能环节（例） | 还缺什么证据 |
|---|---|---|
| 漏检 | 分辨率／浅层特征／阈值过高／匹配失败 | 按尺度分层的漏检统计 |
| 误检 | 分类／背景抑制／阈值过低 | FP 可视化与类别混淆 |
| 定位偏 | 回归头／stride 量化／小框 | IoU 分布、偏移直方图 |
| 重复框 | NMS 阈值／多尺度重复预测 | NMS 前后框数对比 |

判断链模板：

> 观察到的现象 → 可疑环节 → 还缺证据 → 最小对照能否验证 → **当前是否足以改结构（默认：否）**
