# 项目学习笔记统一记录方法

_适用于练手论文、Paper 1及后续启动论文的所有学习笔记。_

---

## 🎯 必须掌握的少量内容

每份笔记只选少量真正构成后续研究前提的掌握单元，不设固定比例，也不追求覆盖所有概念。一个内容只有同时满足以下条件，才列入本区：

- 不掌握它就无法可靠完成下一阶段任务
- 能脱离原文，用自己的话沿知识链连续复述
- 能用指定的最小证据验证，而不是只凭“看懂了”判断
- 能说明它对当前论文实验、结论或研究边界的影响

每个掌握单元必须同时写清“复述要求”和“验证方式”。补充概念可以沿知识链记录，但不进入当前完成门。

## 🔗 知识链

每个主题都按关系记录，而不是把概念拆散：

> 输入或前提 → 核心机制 → 输出 → 怎样评价 → 可能失败 → 对项目的决策

技术流程可换成更合适的链，例如：

> 数据 → DataLoader → forward → loss → backward → optimizer → validation → checkpoint

## ✍️ 灵活记录

每次学习只需在对应链条节点下补充内容，可任选形式：

- 一段自己的话或几个要点
- 手写图、截图或本地文件链接
- Mermaid图
- 公式、手算或代码输出
- 来源与源码位置
- 未解决问题及后续修正

不强制重复填写大表，也不要求一次填完整份笔记。画图参考[Mermaid语法指南](../99_Attachments/Mermaid_Syntax_Guide.md)，公式参考[Markdown数学公式写法](../99_Attachments/Markdown_Math_Syntax_Guide.md)。

- 新理解或修正：
- 证据或例子：

## ✅ 完成门

- 能沿知识链连续讲清主题
- 每个必会单元都通过对应的闭卷复述
- 每个必会单元都留下指定的可检查证据
- 能说明适用条件或失败情况
- 能说明该知识怎样影响当前论文
- 不确定内容明确标记为待核验
