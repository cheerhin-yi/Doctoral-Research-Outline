# 指标
## 一、模型体积与资源消耗
### 1. 参数量
- 模型中所有可学习权重和偏置的**总个数**，单位通常为百万（M）。
- 直接影响模型文件大小和运行时显存占用（参数部分）。
### 2. 模型体积
- 参数存储为文件后的**磁盘占用**（MB/GB）。
- 全精度（FP32）下 1M 参数 ≈ 4MB；半精度（FP16）减半，量化（INT8）可降到约 1MB/M。
### 3. 推理内存占用
- 运行时 GPU 显存消耗 = 参数 + 优化器状态（训练时）+ **中间激活值**。
- 激活值通常是 batch size 大时的显存瓶颈，比参数更易导致 OOM。
### 4. FLOPs / MACs
- **FLOPs**：一次前向传播需要的浮点运算次数（乘、加），反映理论计算量，与硬件无关。
- **MACs**（Multiply-Accumulate Operations）：1 MAC ≈ 2 FLOPs。多数报告 FLOPs。
- 用于客观对比模型“轻重”，不依赖硬件环境。
---
## 二、速度与延迟指标
### 5. FPS
- **每秒处理帧数**。必须注明测试硬件（GPU/CPU型号）、输入尺寸、batch size，否则无可比性。
### 6. 延迟
- **单次推理耗时**（毫秒），从接收输入到输出结果的总时间。实时系统比 FPS 更关键。
### 7. 吞吐量
- **每秒可处理的样本总数**（通常指批量并发）。服务端看吞吐量，端侧看延迟。
### 8. 全流程耗时分解（部署关键）
- **预处理**：图像缩放、归一化等。
- **推理**：纯网络前向时间（多数论文只报这段，容易虚高）。
- **后处理**：如 NMS、解码框坐标。某些模型后处理占 50% 以上时间，必须纳入总延迟。
---
## 三、分类/检索通用效果指标

### 9. 准确率
- 预测正确的比例。**类别均衡**时适用，不均衡时会掩盖问题。
### 10. 精确率与召回率
- **精确率**：预测“正”中真正正的比例（捕得准）。
- **召回率**：所有真正正中被找出的比例（找得全）。
### 11. F1-Score
- 精确率与召回率的调和平均：2×P×R/(P+R)。  
- 类别不均衡或两者需权衡时用。
---
## 四、目标检测专属精度指标：mAP 家族

mAP （mean Average Precision，平均精度均值）是目标检测模型评估中衡量整体检测性能的核心指标。目标检测不仅要分类正确，还需定位准确，因此使用不同 IoU 阈值下的 mAP。
### 12. IoU（交并比）
- 单个框的预测与真实重叠程度：交集面积 / 并集面积。阈值越高，对位置要求越严。
### 13. COCO mAP 标准（目前主流）
| 指标 | 说明 |
|------|------|
| **AP**（或 AP@[.50:.95]） | IoU 从 0.50 到 0.95 步长 0.05 共 10 个值下的平均 AP，**综合定位能力主指标** |
| **AP@50** | 仅 IoU≥0.5 时的 AP，宽松定位，看“是否找到物体” |
| **AP@75** | 仅 IoU≥0.75 时的 AP，严格定位，框必须十分贴合 |
| **APₛ / APₘ / APₗ** | 分别针对小、中、大目标的 AP，暴露尺度偏差 |
### 14. PASCAL VOC mAP
- 仅使用 **AP@50**，历史对比常用，现已逐步被 COCO 指标替代。
---
## 五、目标检测的召回与定位扩展指标

### 15. AR（平均召回率）
- 限制每张图最多输出的框数（如 1、10、100）时计算召回率，衡量**找全能力**。
- 常用 **AR@100**，也有小/中/大目标分开的 AR。
### 16. IoU 改进变体
- 除作为损失函数外，也直接作为定位质量评价指标：
  - **GIoU**：解决无重叠时梯度问题。
  - **DIoU**：加入中心点距离，收敛快。
  - **CIoU**：再加长宽比一致性，回归更稳。
- 论文中有时直接报 “CIoU=0.xx” 来证明定位更好。
### 17. FPPI（每图误检数）
- 固定召回率（如 90%）下，平均每张图的**误检框数量**。  
- **行人检测、自动驾驶**必看，越低越好。
### 18. Log-average Miss Rate
- 在对数空间平均不同 FPPI 下的漏检率，综合反映漏检与误检。行人检测常用。
---
## 六、检测架构效率指标

### 19. 检测头计算量/参数量
- 分离 backbone 后，仅检测头的 FLOPs 或参数量，用于对比“检测头部谁更轻”。
### 20. NMS 依赖与替代
- 传统检测器依赖 NMS 后处理，耗时且有调参成本。  
- NMS-free 架构（如 DETR）可端到端推理，简化部署管线，也是评价设计先进性的隐性指标。
---

## 七、综合评估速查表

| 关注点        | 必看指标                                            |
| ---------- | ----------------------------------------------- |
| **精度**     | COCO AP (AP@[.50:.95])，若重定位质量加看 AP@75，小目标必看 APₛ |
| **漏检**     | AR@100，密集场景下关键                                  |
| **速度（理论）** | FLOPs                                           |
| **速度（实际）** | FPS（标硬件）、总延迟（含预处理+后处理）                          |
| **误报控制**   | FPPI、Log-average Miss Rate（安全场景）                |
| **体积**     | 参数量、模型体积、推理显存                                   |
| **部署便利性**  | 是否需要 NMS、后处理复杂度、最大支持分辨率                         |
# 参数（超参数）
人为设置。
### 1. 与模型参数的区别
- **模型参数**：权重、偏置，训练中通过反向传播自动学习更新。
- **超参数**：学习率、批次大小、网络层数等，需要在训练开始前设定好，训练过程中通常不变（或有预设的调整策略）。
### 2. 常见超参数分类

| 类别        | 例子                                     | 作用                 |
| --------- | -------------------------------------- | ------------------ |
| **网络结构**  | 层数、每层神经元数、卷积核大小、通道数、激活函数类型             | 决定了模型的容量和形态        |
| **优化相关**  | 学习率（lr）、优化器类型（SGD/Adam）、动量、权重衰减（正则化系数） | 控制参数更新的步长和方向       |
| **训练过程**  | 批次大小（batch size）、训练轮数（epochs）、损失函数类型   | 影响训练速度、稳定性和最终效果    |
| **数据相关**  | 输入尺寸（图像高宽）、数据增强策略、类别权重                 | 影响模型的泛化能力和对特定任务的适配 |
| **硬件/效率** | 混合精度（AMP）、梯度累积步数、数据加载进程数               | 在固定资源下最大化训练吞吐      |

### 4. 超参数调整

- 很难一次设对，通常通过经验、网格搜索、随机搜索或自动调参（如 Optuna）来寻找较优组合。
    
- **学习率** 往往是最重要的一个，过大不收敛，过小训练慢。
