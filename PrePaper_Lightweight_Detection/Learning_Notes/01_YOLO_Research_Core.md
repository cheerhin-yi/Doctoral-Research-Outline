# 学习笔记1：从基本YOLO到论文级目标检测

## 你的起点

你已经学习卷积和YOLO基本概念，因此跳过卷积定义、经典CNN历史和YOLO版本年表。现在需要建立“结构—训练—指标—错误—论文实验”的完整链。

## 为什么服务本练手论文

本论文所有结论都建立在可靠YOLO基线上。如果不会解释Head输出、损失、标签匹配、NMS和指标，就无法判断改进来自检测头、训练设置、阈值还是数据泄漏。该笔记直接支撑B0/B1/B2/M的公平比较和小目标错误分析。

## 必学内容

### 1. 完整数据流

需要能够解释：

```text
Image[B,3,H,W]
→ Backbone提取多层特征
→ Neck融合不同尺度
→ Detection Head输出分类与框参数
→ 解码候选框
→ 置信度筛选与NMS
→ Boxes + Classes + Scores
```

- [ ] 标出每层特征图分辨率和通道的变化；
- [ ] 解释浅层高分辨率特征为什么对小目标重要；
- [ ] 说明训练阶段和推理阶段分别在哪一步不同。

### 2. Backbone、Neck与Head

- Backbone：提取局部纹理到高级语义；
- Neck：通过多尺度融合兼顾小、中、大目标；
- Head：预测类别和位置；
- 重点不是背模块名称，而是能判断某个失败是否真由该部分造成。

必须回答：

1. 小目标消失可能发生在哪些下采样位置？
2. 只增加更深网络为什么可能不改善小目标？
3. 提高输入分辨率与修改多尺度特征的代价有何不同？

### 3. 训练目标

掌握以下直觉和最小公式：

- IoU：预测框和真值框的重叠比例；
- 分类损失：预测类别与标签的差异；
- 定位损失：框的位置和尺度误差；
- 标签匹配：决定哪些预测负责哪些真值；
- 类别不平衡：大量背景和少量目标类别会怎样影响训练。

学习输出：写一张表，列出“分类错误、漏检、重复框、定位偏差”分别可能与哪些训练环节有关。

### 4. 推理与NMS

必须理解置信度阈值和IoU阈值会同时改变Precision、Recall和每图候选数。

手工练习：给出3个重叠框、类别分数和阈值，逐步执行NMS，说明哪个框被删除以及为什么。

### 5. 评价指标

必须掌握：

预测框 $B_p$ 与真值框 $B_g$ 的交并比为：

$$
\operatorname{IoU}(B_p,B_g)
=
\frac{|B_p\cap B_g|}{|B_p\cup B_g|}
$$

Precision、Recall与F1为：

$$
\operatorname{Precision}=\frac{TP}{TP+FP},
\qquad
\operatorname{Recall}=\frac{TP}{TP+FN}
$$

$$
F_1
=
\frac{2\,\operatorname{Precision}\,\operatorname{Recall}}
{\operatorname{Precision}+\operatorname{Recall}}
$$

在类别 $c$ 和IoU阈值 $\tau$ 下，AP可写为PR曲线下面积：

$$
\operatorname{AP}_{c,\tau}
=
\int_{0}^{1} p_{c,\tau}(r)\,\mathrm{d}r
$$

对 $C$ 个类别取平均：

$$
\operatorname{mAP}_{\tau}
=
\frac{1}{C}\sum_{c=1}^{C}\operatorname{AP}_{c,\tau}
$$

其中，$TP$、$FP$和$FN$分别表示真正例、假正例和假负例；$p(r)$表示以Recall为横轴时的Precision。实际实现通常采用离散插值而不是直接计算连续积分。

还要理解PR曲线、mAP50、mAP50–95、逐类AP和尺寸分层Recall。mAP50–95通常表示在IoU阈值$0.50,0.55,\ldots,0.95$上计算mAP后再取平均。

本练手论文优先级：

1. AP_small和Recall_small；
2. mAP50–95；
3. 遮挡分层Recall或AP；
4. FPS、时延、参数量、GFLOPs和模型大小；
5. 相同条件下的精度—速度折中。

不能只报告mAP50，因为它对定位质量要求较低，也可能掩盖小目标漏检和速度代价。

### 6. 公开航拍小目标错误分类

对每个错误至少记录：

- 目标尺寸：small/medium/large；
- 飞行高度或像素尺寸；
- 遮挡程度；
- 背景类型；
- 类别；
- 错误类型：漏检、误检、分类错、定位差、重复框；
- 是否属于小目标或遮挡分层。

错误分析的目的不是展示更多图，而是决定是否存在一个值得测试的最小改动。

### 2. 核心概念笔记

| 概念 | 我的解释 | 公开航拍例子 | 适用条件/失败情况 |
|---|---|---|---|
| Backbone | 多层CNN编码器，将输入图像逐步下采样，从浅层纹理（边缘、角点）提取到高层语义（人、车、物体类）。每层输出是不同尺度的特征图；通常输出P3(1/8)、P4(1/16)、P5(1/32)三尺度特征给Neck。 | 航拍640×640输入中，Backbone的P2(1/4=160×160)仍能看见单个行人的轮廓；到P5(1/32=20×20)时一个20像素的小行人只剩不到1个cell，语义几乎丢失。 | 小目标（<32px）在多次下采样后特征消失；只加深Backbone不增加浅层分支，小目标收益为零甚至负。 |
| Neck与多尺度 | 接收Backbone多尺度特征，通过上采样+横向连接（FPN/PAN）融合高分辨率低语义与低分辨率高语义。YOLO11的PAN在P3/P4/P5同时传到底部和顶部，让每个Head都兼有语义与位置。 | P3融合P5上采样后的特征后，能把"这是车"的高层语义放回80×80的精细位置上，避免远处汽车被当成路面纹理。 | 若Neck只传P5的强语义给P3而不保持P3原始分辨率，则小目标定位反而退化；如果增加P2但没有P4/P5语义，P2会产生大量背景误检。 |
| Detection Head | 一组共享或独立的卷积层，把Neck输出的每个特征cell映射成：(1) 锚框偏移或无锚框的dfl分布（xywh）、(2) 类别logits、(3) 目标置信度（YOLO早期）或类内最大分数（新YOLO合并为分类分支）。每个尺度独立预测，后统一解码。 | P3 Head在80×80网格上对每个cell预测3组框+类别，覆盖小行人/小车；P5在20×20上覆盖大巴/大楼。如果航拍输入加了P2(160×160)，才能稳定看到<16px的交通标志。 | Head太宽会使小样本过拟合；多尺度Head参数不共享时，P2/P3/P4会各学各的，参数量≈n_scales×单头参数量。 |
| 标签匹配与损失 | 训练前，每个真值框通过（IoU阈值/中心距离/成本矩阵，如Task-Aligned Assigner）决定由哪个尺度的哪几个预测cell来"负责"预测它。然后计算三类损失之和：分类（BCE/CVFocal）、定位（CIoU或DFL+CIoU）、贡献样本平衡。 | 航拍图中一个8像素的行人，中心落在P3的cell里；如果模型有P2，优先由P2匹配，因为更大的特征图能给更细的梯度；匹配错到P5会导致梯度为0，该行人永久漏检。 | 匹配规则过严（只允许1个正样本）会漏检密集目标；过松会让多个cell抢同一个框，导致NMS后仍有重复框。类别不平衡（背景:目标≈100:1）必须用Focal Loss或正样本权重，否则分类损失被背景淹没。 |
| NMS | 非极大抑制：先按置信度阈值过滤低分框，然后对每类（或class-agnostic）按分数排序，循环取最高分框保留，删除与它的IoU>阈值的其他框，直到处理完。作用是去掉同一目标上的多个重叠预测。 | 航拍密集停放的小车，P3/P4同时预测到同一辆车；不做NMS会输出5~8个重叠框，误报让AP_small看起来高但实际不可用。 | IoU阈值太低（<0.3）会删掉相邻的不同目标（密集漏检）；太高（>0.7）会保留重复框。遮挡下两目标IoU接近阈值，普通NMS会错误删除其中一个，需DIoU-NMS或Soft-NMS。 |
| Precision/Recall/AP | Precision=TP/(TP+FP)：查出的框里多少是对的；Recall=TP/(TP+FN)：全部真值里找出了多少；AP是固定IoU阈值下PR曲线下面积；mAP是跨类别平均；mAP50-95是跨10个IoU阈值(0.5:0.05:0.95)再平均。AP_small/Recall_small只对面积<32²像素的真值统计。 | 航拍大量小目标时，mAP50可能很高（框对了就行，偏差不超过50%），但mAP50-95骤降——因为小目标允许的绝对像素误差极小，框偏3-4像素就被0.95 IoU阈值判成FP。 | mAP50不能替代mAP50-95；AP_small只看小真值但没有限定预测面积，存在用大框"套"小目标刷AP的陷阱。必须同时报告Recall_small确认没有大量漏检。 |

#### 3.1 YOLO完整检测链结构图（YOLO11n P3–P5基线 + 推理/训练分叉）

```mermaid
flowchart TD
    A[输入图像 B×3×640×640] --> B[Backbone: CSPDarknet 系列下采样]
    B --> B1[P2  1/4 = B×c2×160×160  浅层纹理  ★仅B1/M有此输出]
    B --> B2[P3  1/8 = B×c3×80×80   中小目标语义]
    B --> B3[P4 1/16 = B×c4×40×40   中目标语义]
    B --> B4[P5 1/32 = B×c5×20×20   大目标/全局语义]

    B2 --> N1[PAN-Neck 上采样+拼接+卷积]
    B3 --> N1
    B4 --> N1
    B1 -. 仅P2变体 .-> N1

    N1 --> H1[Head P3 80×80]
    N1 --> H2[Head P4 40×40]
    N1 --> H3[Head P5 20×20]
    N1 -. 仅P2变体 .-> H0[Head P2 160×160]

    H1 --> D[解码 ×ywh + 类别分数]
    H2 --> D
    H3 --> D
    H0 -.-> D

    D --> TRAIN[训练分支  损失计算]
    D --> INFER[推理分支  后处理]

    %% 训练分支
    TRAIN --> L1[标签匹配 Task-Aligned Assigner\n按IoU+分类得分分配正样本]
    L1 --> L2[定位损失 CIoU + DFL]
    L1 --> L3[分类损失 BCE/Focal]
    L2 --> LOSS[总Loss = λ1·L_loc + λ2·L_cls + λ3·L_dfl\n反向传播更新参数]
    L3 --> LOSS

    %% 推理分支
    INFER --> P1[置信度阈值筛选  conf≥0.25]
    P1 --> P2[NMS  IoU≤0.7 同类别去重]
    P2 --> OUT[最终输出  Boxes + Classes + Scores\nN ≤ max_det(默认300)]
```

#### 3.2 各阶段输入/输出/张量含义 + 训练/推理差异表

假设 B=16 训练 batch, 推理 B=1；输入尺寸 640×640；类别数 C=10；DFL回归 bins=16。

| 阶段 | 输入张量 | 输出张量 | 张量每维含义 | 训练阶段差异 | 推理阶段差异 |
|---|---|---|---|---|---|
| 输入 | — | [16, 3, 640, 640] / [1, 3, 640, 640] | batch, RGB, H, W | Mosaic/ MixUp/随机HFLS/HSV增强；与gt_boxes配对 | Letterbox保持比例，居中+pad到640，无增强 |
| Backbone P5 | [B, 3, 640, 640] | [B, 1024, 20, 20] | B, channels, H/32, W/32 | 参与BN更新，可能DropPath/StochasticDepth | 冻结BN，运行模式eval() |
| Backbone P4 | 上层输出 | [B, 512, 40, 40] | B, channels, H/16, W/16 | 同上 | 同上 |
| Backbone P3 | 上层输出 | [B, 256, 80, 80] | B, channels, H/8, W/8 | 同上 | 同上 |
| Neck (PAN) | P3,P4,P5 | N3, N4, N5 同尺度通道一致 | 融合后多尺度特征 | 上采样+拼接+C2f都走训练forward；记录梯度 | 完全相同结构，只是不记录梯度 |
| Head P3 | N3 [B,256,80,80] | cls [B,C,80,80] + box [B,4·reg,80,80] | 分类logits / DFL分布 | 不平滑/不解码，直接送入损失 | 解码成xywh像素坐标；sigmoid转分数 |
| Head P4 | N4 | cls/box 同模式 × 40×40 | 同上 | 同上 | 同上 |
| Head P5 | N5 | cls/box 同模式 × 20×20 | 同上 | 同上 | 同上 |
| 解码 — Head输出汇总 | 3尺度Head | [B, 8400, 4+C] | 每个cell×每个anchor（YOLO11为anchor-free，每cell 1组）共80²+40²+20²=8400 | 可选：训练评估时也解码算验证mAP，但不走NMS仅按IOU匹配 | 必须解码成绝对坐标；之后NMS前压平所有尺度 |
| 损失 | Head原始输出 + gt | 标量Loss | L_cls + L_box + L_dfl加权和 | 回传梯度 + 优化器.step + lr_scheduler.step | 不计算；只做推理 |
| 置信度筛选 | 解码结果 [N, 4+C] | [K, 6] x y w h cls score  | K ≤ N, score≥阈值 | 不做；验证时由COCOeval内部按阈值 | 阈值0.001~0.25可调，过低候选爆炸过高漏检 |
| NMS | 筛选后候选 | [M, 6] M≤max_det | 每类或全类别IoU抑制后保留 | 训练时跳过 | 标准MultiClass NMS；可选class-agnostic |
| 最终输出 | NMS输出 | 最终检测集合 | boxes / classes / confidences | — | 可视化/指标统计/下游风险推理 |

关键差异点一句话：**训练=加增强+标签匹配+多损失加权+梯度回传**，**推理=Letterbox+解码+置信度筛选+NMS+输出**；两者共享参数但数据流在Head后分叉。

#### 3.3 IoU / Precision / Recall 手算（公开航拍典型场景）

**设定**：图像 640×640；真值框 G = [200, 300, 220, 320]，即 x1,y1,x2,y2 像素，类别=行人（SMALL：20×20=400像素 < 32²=1024，符合VisDrone小目标定义）。

预测框三个：
- P1 = [202, 302, 222, 322]  score=0.88
- P2 = [210, 310, 225, 328]  score=0.55
- P3 = [400, 100, 450, 140]  score=0.60  （实际是背景误检成车）

**(a) IoU 手算**

交集∩取每个坐标对的min/max：
- 对 P1 和 G：x_overlap = min(222, 220) − max(202, 200) = 18
  y_overlap = min(322, 320) − max(302, 300) = 18
  |P1∩G| = 18 × 18 = 324
  |P1∪G| = (20×20) + (20×20) − 324 = 400 + 400 − 324 = 476
  **IoU(P1, G) = 324/476 ≈ 0.68** → 在 τ=0.5 时是TP；在 τ=0.7 时是FP

- 对 P2 和 G：x = min(225,220)−max(210,200) = 10； y = min(328,320)−max(310,300) = 10
  |P2∩G|=100； |P2|=15×18=270； |G|=400； 并集=270+400−100=570
  **IoU(P2,G)=100/570≈0.18** → 任何τ≥0.2都是FP

- 对 P3 和 G：完全不相交 → **IoU=0**

**(b) Precision / Recall 手算，τ=0.5，conf阈值=0.5**

按score排序：P1(0.88)、P3(0.60)、P2(0.55)，三者都过阈值。
- P1：IoU=0.68>0.5 → TP=1
- P3：无匹配真值 → FP=1
- P2：G已被P1匹配（COCO协议：一对一匹配，最高分优先占）→ FP=2

真值数 G_total = 1， 未匹配的 = 0 → FN=0

**Precision = TP/(TP+FP) = 1/(1+2) = 0.333**
**Recall    = TP/(TP+FN) = 1/(1+0) = 1.000**
**F1 = 2×0.333×1.0 / (0.333+1.0) = 0.5**

> 说明：这就是"只调高分阈值看起来Precision很差"的典型场景——背景误检P3、重叠框P2把FP拉满。如果把阈值调到0.65，只剩P1， Precision=1.0, Recall=1.0, F1=1.0；但换一张图可能就漏检了。这正是PR曲线存在的原因：**单个阈值点无法描述整体性能**。

#### 3.4 NMS 手算（同类别3框重叠，类别=行人）

输入（全部同一类，τ_NMS=0.5，conf阈值=0.2）：

| 候选 | x1 y1 x2 y2 | score |
|---|---|---:|
| A | 100,200,140,260 | 0.92 |
| B | 105,208,142,262 | 0.78 |
| C | 160,220,200,280 | 0.60 |

**逐步执行**：

1. 按score排序：A(0.92) → B(0.78) → C(0.60)。创建保留列表=[]。
2. 取最高分 A → 加入保留=[A]。依次计算A与剩余的IoU：
   - A 与 B：|A∩B| = (140−105)(260−208) = 35×52 = 1820；|A|=40×60=2400；|B|=37×54=1998；并集=2400+1998−1820=2578；IoU=1820/2578≈**0.706 > 0.5** → 删除B。
   - A 与 C：x相交=min(140,200)−max(100,160)= 140−160 ≤0 → **IoU=0 < 0.5** → 保留C。
3. 取下一个最高分剩余框 = C → 加入保留=[A, C]。无更多框。
4. **NMS输出 = {A, C}**。B因为与最高分A重叠过多而被去掉。

> 判断错误的位置：B实际上是和A对同一辆车/同一个人的两次重复预测（比如P3、P4各预测一次），被NMS正确合并。如果NMS τ改成0.8，B会被保留，造成输出出现两个重叠框（重复框错误）。

#### 3.5 mAP50 与 mAP50–95 为什么**不能互相替代**

1. **定义不同**：mAP50只取 τ=0.5 一个IoU阈值；mAP50-95取 τ ∈ {0.50, 0.55, ..., 0.95} 共10个阈值计算AP后再平均。
2. **定位要求不同**：对一个640×640的20×20像素行人为例：
   - 在 τ=0.50：允许框偏大约6-8像素仍判TP → mAP50容易高，像"大致对了就行"
   - 在 τ=0.95：允许框偏差 ≤1-2像素 → 定位稍差就变FP；小目标几乎都被淘汰
3. **真实部署意义不同**：下游风险推理或三维Paper 2需要精确框作为输入。mAP50高但mAP50-95低意味着"检测到了但框不准"，会直接拖累后续风险分级和几何测量。
4. **不能由一个推算另一个**：同模型mAP50与mAP50-95的差不是固定常数——不同类别、不同目标尺寸的差不同，无法线性转换。
5. **论文中常见陷阱**：只报mAP50=0.45让读者误以为"已经不错"，但mAP50-95可能只有0.22；练手论文必须**同时报告mAP50-95 + AP_small + Recall_small**，三者缺一不可。

### 6. 闭卷自测与总结

> 以下回答在不查阅任何资料的情况下完成。

**1. 为什么更大的YOLO不一定更适合实时航拍小目标检测？**
我的回答：更大的YOLO（YOLO11s/m/l/x）主要靠增加Backbone深度和通道数提升中/大目标语义，但航拍80%的真值是<32px的小目标，它们在P3以下就已经丢失，再深的Backbone也拿不回来。同时更大的模型：(1) GFLOPs暴涨，640输入下11x比11n慢约5-8倍，直接违反实时约束；(2) 参数量大会在小样本航拍数据集上过拟合；(3) 浅层分辨率并没有提高，P2/小目标的cell数和n版本一样没增多，所以AP_small经常根本不涨甚至更差。真正提升小目标靠的是**加入P2/P2–P4尺度重配**，而不是堆大模型。

**2. 为什么提高输入分辨率不能直接证明网络结构创新？**
我的回答：提高分辨率（比如640→1280）就是让同一个cell覆盖的真实像素更小，属于**计算预算增加**，任何模型用了都能涨AP_small——相当于你把相机飞到更低高度，不是网络结构更聪明。公平对照必须固定**输入尺寸、batch、epoch、seed、硬件**全部一致，B0/B1/B2/M必须用完全相同的输入（研究计划已写死640默认）。如果M比B0在相同640输入下AP_small高+延迟/GFLOPs下降，那是结构创新；如果M只是开1280而B0开640，那是花钱堆算力，审稿人一眼会指出来。

**3. Precision提高而Recall_small下降时，练手论文的核心结论会怎样变化？**
我的回答：练手论文的两个核心主张是C0-1（小目标精度-计算折中）和C0-2（真实推理速度）。Precision提高而Recall_small下降通常是置信度阈值调得太高或模型保守。**如果Recall_small显著下降（>3-5个百分点），C0-1就不成立**——因为我们的应用是铁路巡检漏检危险物，宁可有一点误检（Precision略降），也不能漏掉一个小的侵界障碍。正确的比较方式必须在**相同置信度阈值+相同NMS协议**下看完整PR曲线，或固定Recall=0.9时比较Precision；不能各自挑一个最优阈值报数字。如果M只有Precision上升而Recall_small下降，就要回到训练排查标签匹配或共享头是否抑制了P2的召回能力。

**4. 怎样公平比较YOLO11n/s/m？**
我的回答：至少固定7项一致：(1) 完全相同数据+官方划分；(2) 相同输入尺寸+Letterbox；(3) 相同预训练权重来源（或都从0训练）；(4) 相同epoch/batch/optimizer/seed列表×3；(5) 相同数据增强（Mosaic/MixUp系数、关闭时间完全一致）；(6) 评价协议：相同COCOeval、相同max_det、相同尺寸分层规则；(7) 速度测试：相同硬件、batch=1、相同预热次数(≥100)、相同计时范围(只测forward+后处理还是连preprocess)。只比较GFLOPs和参数量**不算公平**，因为不同算子在同一硬件上的实际延迟并不线性相关。最终必须有真实延迟/FPS数字。

**5. 哪类错误才能合理触发一个结构改动？**
我的回答：必须同时满足三条：(1) **有证据的系统性错误**：不是1-2张图，而是在≥10%验证集小目标上**一致发生**的某一类错误（比如漏检<16px目标、遮挡下NMS误杀、重复框）；(2) **能回链到结构环节**：错误类型→Head/Backbone/Neck/NMS的具体哪一步能解释（比如小目标漏检→没有P2分支；遮挡重复框→普通NMS）；(3) **改动是最小唯一变量**：只改一个模块，不叠加注意力、损失、增强等。练手论文的LSM-Head改动依据是"小目标系统性漏检+B1普通P2代价太高"——这就是合理触发。而"看别人论文加了CBAM所以我也要加"属于跟风，没有证据链，是被阶段指南明确禁止的。
