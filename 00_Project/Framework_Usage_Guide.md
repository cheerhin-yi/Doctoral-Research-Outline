# 当前项目框架详细使用说明

**适用版本**：按16个研究周弹性推进版
**适用对象**：项目本人、指导教师讨论、Codex周检查
**当前唯一实验主任务**：Paper 1——无人机铁路开放环境风险感知

这套框架的目的不是让你每天打卡，而是保证学习、文献、实验和论文写作始终围绕可验证的研究问题推进。一个“研究周”是一个研究节点，不等于七个自然日；它可以根据实际时间跨越多个自然周。

## 1. 先记住四条规则

1. **同一时间只推进一个研究周。** 当前研究周的MUST任务没有完成时，不同时启动下一研究周。
2. **证据比工时重要。** 每个研究周建议累计12–18小时，但低于这个时间不会自动扣分；没有笔记、文件、日志或结果证据，投入再多时间也不算完成。
3. **任务可以拆开做。** 一项3–5小时的任务可以分成多个30–90分钟会话，不要求当天做完。
4. **不虚构结果。** 数据、环境或算力不足时，记录预注册、配置、可执行步骤和阻塞证据，不填写不存在的指标。

## 3. 第一次使用时怎么开始

如果你还没有正式填写任何研究周，默认从W01开始。

1. 阅读[项目总计划](Master_Plan.md)，确认当前只做Paper 1，不启动Paper 2–7的大规模实验。
2. 打开[研究周状态表](Weekly_Status.md)，把W01状态从“待开始”改为“进行中”，填写实际开始日期。
3. 打开[W01研究周模板](Weekly_Notes/W01_研究边界与数据审计.md)，先填写“研究目标”“最关键判断”和“明确不做的事情”。
4. 只选择T01开始。若今天只有30分钟，就把T01拆成一个30分钟子任务，例如“只阅读Project Charter中的Primary Claim并写三句自己的理解”。
5. 结束时填写一次“实际学习与研究会话记录”，写清证据路径和下一最小动作。
6. 下次继续当前研究周尚未完成的MUST任务，不因为日期变化自动进入W02。

## 4. 如何根据自己的时间安排研究周

研究周长度由完成门决定，不由日历决定。

| 近期可用时间 | 建议做法 | 研究周可能持续时间 |
|---|---|---|
| 每周约3–5小时 | 每次只完成一个MUST子任务；停止COULD，谨慎安排SHOULD | 通常会跨多个自然周 |
| 每周约6–10小时 | 先完成概念、协议和最小闭环，再安排完整运行 | 可能需要一至数个自然周 |
| 每周约12–18小时 | 按任务池推进，但仍允许任务跨天 | 有条件在一个自然周左右完成 |
| 某周几乎没有时间 | 记录暂停原因和恢复时的第一动作，不创建虚假进度 | 当前研究周保持“进行中” |

表中的持续时间只是容量参考，不是截止日期。遇到数据审计、训练、标注或文献核验等耗时工作时，研究周自然延长。

## 5. 每个研究周的标准工作流

### 5.1 开始研究周

只做四件事：

1. 在[研究周状态表](Weekly_Status.md)填写开始日期和“进行中”。
2. 在对应周模板明确研究目标和本周不做的工作。
3. 浏览T01–T08，但只选择第一个可执行的MUST任务。
4. 检查任务需要更新哪些学习笔记、协议或实验文件。

### 5.2 每次有时间时

一次会话可以只有30分钟，也可以是几小时。开始前先回答：

- 我现在推进哪个任务ID？
- 这次结束时必须留下什么文件或记录？
- 如果做不完，下一最小动作是什么？

结束后立即在周模板的“实际学习与研究会话记录”增加一行。不要等到周末凭记忆补写。

### 5.3 时间不足或任务卡住时

- MUST未完成：继续留在当前研究周，把任务缩小，不把整项任务原样拖到以后。
- SHOULD未完成：明确写“顺延到Wxx”或“删除”。
- COULD未完成：直接删除，不记为欠账。
- 连续两次会话没有实质进展：记录阻塞原因，并把下一动作缩小到30–90分钟可验证的步骤。
- 数据或算力不可用：完成配置、预注册、运行命令和阻塞证据，不填写实验结果。

### 5.4 结束研究周

满足以下条件后才能提交检查：

- T01–T05和T07共6个MUST任务完成且有证据；
- 闭卷自测达到75分；
- 交付物核对完成；
- 研究周复述与反思已填写；
- 每项失败或阻塞都有下一步处理；
- 周模板中的证据能打开或能定位到对应文件。

检查通过后，再把[研究周状态表](Weekly_Status.md)更新为“已通过”，然后启动下一研究周。

## 6. 研究周模板逐项怎么填写

以下说明适用于[W01–W16全部模板](Weekly_Notes/)。

### 6.1 顶部信息

- **自然日期范围**：填写第一次实际开始和最终通过检查的日期。未结束时只填开始日期。
- **实际投入**：累加真实会话时长，不需要凑够12–18小时。
- **状态**：只使用“待开始、进行中、待检查、需补强、已通过”。
- **对应笔记**：模板已给出；实际学习后要同步更新对应N笔记。

### 6.2 本研究周目标

- **研究目标**：写成可检查的产出，例如“冻结YOLO11基线的数据划分、配置和评价指标”。不要写“学习YOLO”这种无法判断完成与否的目标。
- **最关键、可证伪的判断**：写一个可能被证据否定的判断，例如“当前数据加载和类别映射足以支持无泄漏基线训练”。
- **明确不做的事情**：用于控制范围，例如“不调大量超参数、不提前比较Paper 2方法”。

### 6.3 本研究周任务池

任务状态建议这样填写：

- `☐`：未开始；
- `进行中`：已经产生部分证据，但未达到完成判据；
- `☑`：达到完成判据且证据路径已记录；
- `顺延至Wxx`：只用于SHOULD；
- `删除：原因`：用于SHOULD或COULD。

不要因为“看过资料”就勾选完成。必须同时满足该行的“预期证据”和“完成判据”。

### 6.4 实际学习与研究会话记录

每次会话填写一行。推荐格式示例：

| 会话日期 | 时长 | 任务ID | 实际完成的具体工作 | 证据链接/路径 | 阻塞与下一最小动作 |
|---|---:|---|---|---|---|
| YYYY-MM-DD | 45min | T03 | 写出YOLO数据流并完成一组标签可视化检查；尚未运行训练 | `03_Learning/N02_...md`、待创建的检查日志 | 类别映射仍待核对；下次只检查3个类别ID |

“实际完成”只写已经发生的工作；“下一最小动作”要具体到下次打开电脑就能开始。

### 6.5 D1 / D3 / D7间隔复习

- **首学日期**：第一次真正理解或练习该概念的日期。
- **D1、D3、D7**：分别在约1、3、7天后，不看资料复述核心概念，再对照笔记修正。
- **仍会混淆的点**：写具体差异，例如“Open-set与Open-world是否包含增量学习仍会混淆”，不要只写“还不熟”。

如果研究周跨越很久，间隔复习仍按自然日期进行，不需要等待研究周结束。

### 6.6 闭卷自测

先关闭资料，用自己的语言回答；之后再用不同颜色或“修正：”补充。评分重点是能否解释、比较、举铁路场景反例，而不是背定义。

### 6.7 文献阅读

周模板只记录与当前任务直接相关的论文。完整元数据写入[文献矩阵](../01_Literature/Literature_Matrix.md)，重要论文再建立单篇阅读笔记。

- **读到的证据**：写论文具体做了什么，不写“效果很好”。
- **与Paper 1关系**：写支持、冲突、可复用或仅作背景。
- **局限/冲突**：写数据、任务定义、指标或假设与本项目哪里不同。
- **已核验**：只有实际核对原文标题、作者、年份、出处和链接后才能勾选。

### 6.8 实验或最小练习

即使只是手算指标、可视化标签或小样本过拟合，也要先填写：

- Hypothesis：预计会观察到什么；
- Independent Variable：主动改变什么；
- Control：哪些条件保持不变；
- Baseline：和什么比较；
- Dataset/Split：用哪份数据和划分；
- Metrics：用什么量化；
- Success Criterion：什么结果才支持继续；
- Failure Interpretation：失败分别可能说明数据、实现、模型或假设有什么问题；
- Run ID：正式运行必须关联唯一ID。

### 6.9 交付物核对

逐项确认文件真实存在、内容可复核、结论没有超过证据。配置、数据划分、随机种子、版本和原始指标应能追踪。

### 6.10 研究周复述与反思

- 200字复述必须自己写，不能直接复制学习笔记。
- “最大失败”要写事实和影响。
- “失败说明了什么”要区分数据问题、实现问题和研究假设问题。
- “下一研究周最先做的一件事”必须是一个可执行动作。
- 对不再服务主张的工作，明确停止或删除。

### 6.11 提交给Codex检查

完成后可以直接对Codex说：

> 请检查W02。我已填写W02周模板，并更新N01、N02、实验跟踪表和相关日志。请按照Review Rubric评分，把结果写入W02_Review.md，并更新Weekly_Status。重点检查数据划分、YOLO基线复现和我对检测指标的理解。

“Codex评审区”由Codex根据证据填写，你不要预先替自己填写正式得分。

## 7. N01–N16学习笔记怎么填写

学习笔记不是一次性教材，而是随研究逐步生长的知识库。只填写当前任务需要的部分，不要求先把整篇笔记补满。

| 章节 | 应填写什么 | 合格标准 |
|---|---|---|
| 1. Why | 为什么当前论文需要这个知识 | 能指出它解决Paper 1或后续论文的哪个具体问题 |
| 2. Intuition | 不用公式解释直觉 | 能用铁路无人机场景讲清楚 |
| 3. Core Concepts | 最关键的概念、组件和差异 | 不堆术语，概念之间关系明确 |
| 4. Minimal Math | 最少必要公式、符号和前提 | 每个符号有含义，知道公式何时失效 |
| 5. Input / Output | 输入、输出、形状、单位和有效性 | 能连接上下游模块 |
| 6. Code | 最小代码、伪代码、配置或运行方式 | 能验证一个概念，不追求完整框架 |
| 7. Railway Example | 对应铁路无人机实例 | 包含场景、输入、预期输出和风险 |
| 8. Paper Connection | 与哪篇论文、哪个模块、哪个主张连接 | 能指向具体文件、Claim或Run |
| 9. Classic Papers | 奠基性工作 | 元数据和链接已核验 |
| 10. Recent Papers | 最新且接近本项目的工作 | 写明新颖性冲突和可复用点 |
| 11. My Understanding | 不看资料后的个人复述 | 由你本人填写，Codex只检查和纠错 |
| 12. Failure / Limitation | 方法失败条件和不适用边界 | 至少联系一个铁路场景失败例 |
| 13. Open Questions | 尚未解决且值得验证的问题 | 问题可以转化为阅读或实验动作 |
| 14. Mini Experiment | 最小验证练习 | 有假设、输入、步骤、指标和证据 |

笔记底部的复习卡片按D1、D3、D7、D14复习。卡片背面用自己的语言写，不复制定义。自测先闭卷回答，再请求Codex指出错误。

## 8. 文献系统怎么使用

文献工作遵循“检索记录→文献矩阵→单篇笔记→创新台账”四步。

### 8.1 Search Log

每次成批检索都在[Search Log](../01_Literature/Search_Log.md)增加一行，保存数据库、完整检索式、时间范围、纳入/排除标准和入选ID。这样以后能够说明文献是如何找到的，而不是随意挑选。

### 8.2 Literature Matrix

每篇候选文献一个ID。未核验原文前，Title、Year、Venue和链接都标记为“待核验”，不得凭记忆补全。

优先填写：Problem、Dataset、Input、Output、Method、Metrics、Limitations、Closest to Paper、Innovation Conflict和Priority。`Must Read`表示需要进入单篇精读，不等于论文质量高。

### 8.3 单篇阅读笔记

复制[单篇阅读模板](../01_Literature/Reading_Notes/Paper_Reading_Template.md)，文件名建议为`Lxxx_简短标题.md`。重点回答论文真正解决了什么、在哪些假设下成立、与本项目最接近哪里、哪些内容不能直接复用。

### 8.4 进入Innovation Ledger

只有当文献改变了“最近工作、剩余缺口、方法设计或新颖性风险”时，才更新创新台账，并记录触发文献ID和理由。

## 9. Innovation Ledger怎么维护

每个候选创新都要持续维护以下链条：

> Candidate Innovation → Closest Prior Work → Existing Work → Remaining Gap → Our Hypothesis → Method → Evidence → Novelty Risk

- 新论文与方案高度相似：提高Novelty Risk，缩小或重写主张。
- 实验不支持假设：更新Evidence和Hypothesis，不用增加复杂模块掩盖负结果。
- 只是代码工作量很大：不能作为创新保留理由。
- 新颖性风险为High：优先安排检索和主张调整，不继续扩大实验成本。

W10是创新复核节点，指第10个研究周，不是日历中的第10周。

## 11. 单次实验的完整记录流程

### 11.1 运行前

1. 在Experiment Tracker找到对应Run ID。
2. 从[单次实验模板](../13_Experiment_Log/Experiment_Log_Template.md)复制一份记录，建议文件名为`Rxxx_简短名称.md`。
3. 完成预注册：Hypothesis、变量、Control、Baseline、Dataset/Split、Metrics、成功判据和失败解释。
4. 填写代码提交、配置、依赖、硬件、随机种子、启动命令、预计时长和停止条件。
5. 只有数据、标签、指标和最小闭环检查通过后，状态才能从TODO改为READY。

### 11.2 运行中

- 状态改为RUNNING；
- 保存日志、配置和输出位置；
- 任何重启、参数修改和异常都要记录；
- 不覆盖之前的失败输出，保留失败Run作为证据。

### 11.3 运行后

- COMPLETE：运行有效且原始输出齐全；
- FAILED：运行异常或无效，需要说明原因；
- CUT：经过研究判断决定不再执行；
- 更新Experiment Tracker和[Run Index](../13_Experiment_Log/Run_Index.md)；
- 区分“主要结果”“可以支持的结论”和“不能支持的结论”；
- 将论文级图表登记到[图表清单](../14_Figures/README.md)。

实验失败不等于没有产出。只要失败原因、证据和下一决策完整，它仍然是有效研究记录。

## 12. 数据、代码和图表如何管理

### 12.1 数据

在[数据登记表](../11_Datasets/README.md)保存Dataset ID、官方来源、许可、本地位置、版本或哈希、用途和状态。大型数据不提交Git；未核验许可前不假定可以公开使用。

### 12.2 代码

- 每个正式实验必须有Run ID和配置；
- 先做标签可视化、手算指标和小样本过拟合，再跑完整训练；
- 指标保存为JSON或CSV，不只保留截图；
- 不在代码中保存令牌、密钥、绝对私人路径或未授权数据；
- 不为未来可能用到的功能提前搭建复杂框架。

### 12.3 图表

每张论文图表必须有唯一ID、对应Claim、来源Run/Table和生成方式。手工调整过的图也要保留原始数据和生成来源。

## 13. Codex如何检查你的研究周

Codex按[Review Rubric](Review_Rubric.md)评分：

| 维度 | 分值 | 重点 |
|---|---:|---|
| 完成度 | 20 | MUST和交付物是否真实完成 |
| 概念理解 | 25 | 是否能用自己的语言解释和比较 |
| 实验与分析 | 25 | 假设、变量、对照、指标和失败解释是否完整 |
| 证据与可复现性 | 20 | 文件、配置、日志、种子和原始指标是否可追踪 |
| 反思与计划 | 10 | 是否识别真正障碍并给出可执行下一步 |

评分结果写入`00_Project/Reviews/Wxx_Review.md`：

- 90–100：可进入下一研究周；
- 75–89：基本通过，登记最多3项明确补强任务；
- 60–74：继续当前研究周，先补关键证据；
- 0–59：缩小任务并重做核心部分。

工时不是单独评分项。请不要为了提高分数虚报时间或补写不存在的工作。

## 14. 与老师讨论时怎么提取材料

讨论前不需要展示整个仓库，优先准备五项：

1. [研究周状态表](Weekly_Status.md)：当前在哪个节点、用了多久、最大阻塞是什么；
2. 当前研究周模板：已经产生哪些证据；
3. [Project Charter](../04_Paper1_OpenWorld_Risk/Project_Charter.md)：问题、C1/C2和反主张；
4. [Innovation Ledger](../02_Innovation/Innovation_Ledger.md)：最近工作、剩余缺口和新颖性风险；
5. Experiment Tracker或关键表图：下一步为什么值得做。

讨论结论要写回对应文件：方向变化写Project Charter，创新变化写Innovation Ledger，实验变化写Experiment Plan/Tracker，时间与优先级变化写当前研究周模板。

## 15. 常见错误及正确处理

| 常见错误 | 正确处理 |
|---|---|
| 日期到了就自动进入下一周 | 只看当前研究周完成门 |
| 为了“跟上进度”同时做W02和W03 | 先完成W02的MUST并检查 |
| 花了很多时间但没有文件或日志 | 补充可复核证据后再标完成 |
| 只记录最好的一次实验 | 保存全部有效Run、种子和失败记录 |
| 文献元数据凭记忆填写 | 标“待核验”，核对原文后再确认 |
| 看到相似论文就继续堆模块 | 更新Novelty Risk，先缩小或重写主张 |
| 没有GPU就填写预期指标 | 只记录配置、预注册和阻塞证据 |
| 学习笔记复制教程 | 用自己的语言、铁路实例和最小实验重写 |
| SHOULD/COULD长期堆积 | 明确顺延或删除，不形成隐性欠账 |
| 将检测置信度直接当风险概率 | 分开记录检测、未知性、风险和校准语义 |

## 16. 一个完整但不虚构结果的示例

假设当前在W02，今天只有60分钟：

1. 在W02任务池选择T02“检查数据加载、类别映射和数据隔离”。
2. 把这次目标缩小为“抽查10张图的标注框与类别ID”。
3. 在N02补充检测输入/输出和类别映射说明。
4. 完成可视化检查后保存检查脚本或图片索引；如果数据尚未获得，就先写检查字段和执行步骤。
5. 在会话记录填写真实时长、完成内容、证据路径和下一动作。
6. T02尚未覆盖训练/验证/测试隔离时，状态仍写“进行中”，不勾选完成。
7. 下次继续T02；达到完成判据后再勾选，然后选择下一个MUST任务。

这个过程不要求当天训练YOLO，也不要求为了计划节点虚构基线结果。
